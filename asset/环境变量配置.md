# 环境变量配置

Meridian 使用 **3 个 env 文件**，职责不同。无论 Docker 还是本地直接运行，都需要先完成本节配置。

## 1. 复制模板

在项目根目录执行：

```bash
cp .env.example .env
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env   # 仅本地直接运行前端时需要
```

## 2. 文件职责

| 文件 | 作用 |
|------|------|
| `.env` | Docker Compose 用：PostgreSQL、本地模型宿主机路径 |
| `backend/.env` | 后端运行时配置：LLM、Embedding、JWT 等 |
| `frontend/.env` | 前端开发时 API 地址（Docker 生产模式不需要） |

---

## 3. 根目录 `.env`（Docker 专用）

| 变量 | 必填 | 说明 |
|------|------|------|
| `POSTGRES_USER` | ✅ | 数据库用户名 |
| `POSTGRES_PASSWORD` | ✅ | 数据库密码 |
| `POSTGRES_DB` | ✅ | 数据库名 |
| `BGE_MODEL_PATH_HOST` | 本地模型时 | **宿主机** BGE-M3 模型目录的绝对路径，挂载到容器内 `/models/bge-m3` |

示例：

```env
POSTGRES_USER=meridian
POSTGRES_PASSWORD=your_password
POSTGRES_DB=meridian
BGE_MODEL_PATH_HOST=D:/models/bge-m3
```

> **纯 API 嵌入模式**：即使设置了 `SILICONFLOW_API_KEY`、程序不会加载本地模型，`docker-compose.yml` 仍会挂载 `${BGE_MODEL_PATH_HOST}`。请填一个有效目录，或自行去掉 compose 里对应的 volume。

---

## 4. `backend/.env`

### LLM / Agent（必填，对话功能）

| 变量 | 说明 |
|------|------|
| `API_KEY` | LLM API Key |
| `URL` | OpenAI 兼容 API 地址 |
| `MODEL` | 模型名 |

### Embedding（二选一）

| 模式 | 配置 | 说明 |
|------|------|------|
| **API 嵌入（推荐）** | 填写 `SILICONFLOW_API_KEY` | 走 SiliconFlow，仅 **dense** 向量；无需本地下载大模型 |
| **本地 BGE-M3** | 留空或删除 `SILICONFLOW_API_KEY`，配置 `BGE_MODEL_PATH` | 本地可计算 dense / sparse / colbert，但当前入库默认只写 dense，检索也仅使用 dense |

本地模型路径说明：

- **Docker**：`BGE_MODEL_PATH=/models/bge-m3`（容器内固定路径，配合根目录 `BGE_MODEL_PATH_HOST` 挂载）
- **直接运行**：`BGE_MODEL_PATH=D:/models/bge-m3`（填本机绝对路径）

相关变量（本地模型可选）：

| 变量 | 说明 |
|------|------|
| `HF_HUB_OFFLINE` | 设为 `1` 时离线加载 Hugging Face 模型 |
| `TRANSFORMERS_OFFLINE` | 设为 `1` 时 Transformers 离线模式 |

### PDF 解析

| 变量 | 必填 | 说明 |
|------|------|------|
| `MINERU_TOKEN` | PDF 入库时 | MinerU PDF 解析 Token |

### 数据库

| 变量 | 必填 | 说明 |
|------|------|------|
| `DATABASE_URL` | 直接运行时 | Docker 模式由 compose 自动注入，无需手填 |

直接运行示例：

```env
DATABASE_URL=postgresql+asyncpg://meridian:your_password@localhost:5432/meridian
```

### 服务与安全

| 变量 | 必填 | 说明 |
|------|------|------|
| `SECRET_KEY` | ✅ | JWT 密钥，生产环境务必修改为长随机字符串 |
| `ALGORITHM` | 可选 | JWT 算法，默认 `HS256` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 可选 | Token 过期时间（分钟） |
| `PORT` | 可选 | 后端端口，默认 `8897` |
| `ALLOWED_ORIGINS` | 直接运行时 | 前端 dev 地址，需包含 Vite 端口（当前为 `5180`） |
| `ALLOW_PRIVATE_URLS` | 可选 | 是否允许抓取内网 URL，默认 `false` |

直接运行 `ALLOWED_ORIGINS` 示例：

```env
ALLOWED_ORIGINS=http://localhost:5180,http://127.0.0.1:5180,http://localhost:8080,http://127.0.0.1:8080
```

### 评测（可选）

| 变量 | 说明 |
|------|------|
| `RAGAS_API_KEY` | RAGAS 评测用 LLM API Key |
| `RAGAS_BASE_URL` | RAGAS 评测用 API 地址 |
| `RAGAS_LLM_MODEL` | RAGAS 评测用模型名 |

---

## 5. `frontend/.env`（仅本地直接运行）

| 变量 | 说明 |
|------|------|
| `VITE_API_URL` | 后端地址，默认 `http://127.0.0.1:8897` |

Docker 模式下前端经 Nginx 反代访问后端，**不需要**此文件。

---

## 6. 配置检查清单

- [ ] LLM：`API_KEY` / `URL` / `MODEL` 已填写
- [ ] Embedding：已选择 API（`SILICONFLOW_API_KEY`）或本地（`BGE_MODEL_PATH`）之一
- [ ] PDF：如需入库 PDF，已填写 `MINERU_TOKEN`
- [ ] JWT：`SECRET_KEY` 已修改（生产环境）
- [ ] Docker：根目录 `.env` 中 PostgreSQL 与 `BGE_MODEL_PATH_HOST` 已配置
- [ ] 直接运行：`DATABASE_URL`、`ALLOWED_ORIGINS`、`frontend/.env` 已配置

配置完成后，选择启动方式：

- [Docker 启动](./Docker启动.md)
- [本地直接运行](./本地直接运行.md)
